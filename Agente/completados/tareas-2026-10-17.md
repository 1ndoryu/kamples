### 4. El chat individual no abría: la ruta perdía su id

`/mensajes/chat/:conversacionId` estaba declarada **sin `params`**. `resolverPropsParaRuta` solo
inyecta parámetros con nombre cuando la ruta los declara; sin esa clave, el id de la URL se
pierde en silencio y el chat no recibe conversación. Además, `/mensajes/<id>/` tampoco valía: el
router lo resuelve por **prefijo más largo** contra `/mensajes/` y vuelve a pintar la lista.

Arreglo (commit `92cd9ac`): la ruta declara `params: ':conversacionId'`, el hook lo parsea con
validación (`Number.isInteger(id) && id > 0`, si no `null`) y la isla muestra «No se especificó
una conversación» cuando no hay id. `useMensajesIsland.ts:83` navega ya a `/mensajes/chat/<id>/`.

**Regla general que deja este defecto:** una ruta sin `params` pierde su id de URL sin avisar.
Vale para cualquier ruta nueva con parámetro.

### 6. Defecto de herramienta: el wrapper del cliente de escritorio no corría en Linux

`scripts/launch-tauri.mjs:126` hacía:

```js
spawn('cargo run --bin glory-backend', { cwd: projectRoot, stdio: 'inherit', shell: isWin, ... })
```

Con `shell: false` —que es lo que queda en Linux— Node trata la cadena entera como **nombre de
programa**, no como línea de órdenes, y muere con `ENOENT: spawn cargo run --bin glory-backend`.
Es decir: **el único wrapper sancionado del cliente Tauri no podía arrancar en la 89**, que desde
la retirada del toolchain de Rust del portátil (2026-10-16) es el único sitio donde se compila.

Arreglo, programa y argumentos por separado:

```js
spawn(cmdName('cargo'), ['run', '--bin', 'glory-backend'], { cwd: projectRoot, stdio: 'inherit', env: { ...process.env } })
```

Es el caso que la usuaria describió como «si la herramienta es la que falla, arregla la
herramienta primero»: sin esto, el testigo del cliente de escritorio era inalcanzable por la vía
sancionada. Commit propio, revisado antes de cerrar.
