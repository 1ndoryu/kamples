# Marca: una sola fuente

`marca.json` es la única fuente del nombre. Todo lo demás se genera o se lee de ahí;
ningún fichero escribe «Kamples» a mano.

## Dos niveles, a propósito

| Nivel | Claves | ¿Se puede cambiar? | Por qué |
|---|---|---|---|
| Nombre visible | `nombre`, `nombreCorto` | Sí, cuando se decida la marca definitiva | Solo aparece en textos, títulos, bandeja y correos |
| Identidad | `slug`, `identifier`, `esquemaEnlace`, `carpetaDatos`, `dominio` | **No**, sin migrar datos | Ya existen equipos con datos dentro que dependen de ellas |

Kamples es un nombre temporal: por eso el nombre visible y la identidad están separados.
Cambiar `nombre` no toca ni un byte en disco; cambiar `identidad` sí.

## Flujo

```bash
npm run marca          # regenera constantes y parchea tauri.conf.json
npm run marca:check    # falla si algo quedó desfasado (para el gate)
```

`scripts/marca/generar.mjs` valida el nombre (`/^[\w \-.&']{1,40}$/u`) y escribe:

- `src/marca.rs` y `clients/desktop/src-tauri/src/marca.rs` — `NOMBRE`, `NOMBRE_CORTO`,
  `IDENTIDAD_*`, `SITIO_URL`
- `frontend/src/marca.ts` — `NOMBRE`, `NOMBRE_CORTO`, `IDENTIDAD_*`, `CABECERA_AUTH`
- parchea `clients/desktop/src-tauri/tauri.conf.json`: `productName`, `identifier` y
  `plugins['deep-link'].mobile[0].scheme[0]`

Los tres ficheros generados llevan una cabecera «GENERADO … no editar a mano».

## Dónde se consume

- **Rust backend** — asuntos y plantillas de correo, SEO de perfiles y blog, remitente SMTP
  por defecto.
- **Rust Tauri** — título de ventanas, bandeja, página de error y HTML de retorno de OAuth.
- **Front** — títulos de ruta (`routes.ts`), nombre de carpeta al descargar
  (`descargarArchivo.ts`), y los textos con el nombre escrito como `{marca}` en
  `es.json`/`en.json`/`ja.json`: `useT.ts` inyecta `{ marca: NOMBRE }` en **todas** las
  interpolaciones, así que un `{marca}` nuevo en cualquier idioma funciona sin tocar el hook.
- **HTML estático** — `<title>%MARCA%</title>`; el plugin `vite-plugins/marca-html.ts` lo
  sustituye en dev y en build. Un HTML no puede importar TypeScript, de ahí el marcador.

## Qué exige migrar datos si se cambia

Todo esto viaja con `identidad`, no con `nombre`:

| Depende de | Qué rompe si cambia sin migrar |
|---|---|
| `carpetaDatos` (`KamplesDatos`) | La app abriría una carpeta de datos nueva y vacía |
| `slug` como rol/base de Postgres | El clúster local existente no se encontraría |
| `identifier` (`app.kamples.desktop`) | Windows trata la app como otra: WebView2, notificaciones, asociaciones |
| `esquemaEnlace` (`kamples://`) | Un intent-filter ya publicado no se renombra gratis |
| `CABECERA_AUTH` (`X-Kamples-Auth`) | Contrato con el backend desplegado |
| Rutas `/wp-json/kamples/v1/*` | Compatibilidad con el front legacy |
| Claves `localStorage` (`kamples_idioma`, …) | Preferencias del usuario se pierden |

Migrar la carpeta y el clúster es un procedimiento aparte: copiar
`%LOCALAPPDATA%\KamplesDatos`, `ALTER ROLE … RENAME` / `ALTER DATABASE … RENAME`, renombrar
la tabla `_kamples_migraciones` y revisar `keyring` si guarda el servicio por slug.

## Lo que se queda con el literal, a propósito

- **Identificadores de código**: `LogoKamples`, `KamplesSync`, `KamplesPlanId`, `_kamples_migraciones`,
  claves de caché `kamples_*`, `LS_KEY_TOKEN = 'kamples_auth_token'`. Son contrato con datos y
  binarios ya escritos; renombrarlos es la migración de `identidad`, no un cambio de marca.
- **Crates y paquetes**: `glory-backend`, `kamples-desktop`, `kamples_desktop_lib`. Cambiarlos
  obliga a tocar `Cargo.lock`, el `--bin` de los wrappers y las rutas `.exe` instaladas.
- **Prompts de IA** (`MODERATION_SYSTEM_PROMPT`, `VISION_SYSTEM_PROMPT`) y las `description` de
  Stripe en los tests: no los ve la usuaria; el nombre del producto no cambia su comportamiento.
- **Correos de contacto** (`dmca@kamples.com`, `privacy@kamples.com`): van con el dominio, que es
  identidad.

## Regla

1. Se edita `marca.json`.
2. `npm run marca`.
3. `Arranque app "KAMPLES"` para recompilar front y exe.
4. Se reemplazan los ficheros de programa en `C:\Users\Owner\Apps\KAMPLES`; los datos no se
   tocan.
